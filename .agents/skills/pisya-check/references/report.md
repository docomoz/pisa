# Отчёт одного прогона

Сохрани `report.md` в `build/audits/<дата-время>/`. Время указывай с часовым
поясом. Не коммить приватные логи, аудио, расшифровки и снимки реальной библиотеки.
При audit-only продуктовый коммит не нужен; изменения самой процедуры коммить
по правилам проекта.

## Обязательные поля

- Режим, дата, HEAD, ветка; идентификатор снимка исходников и зависимостей.
- Изменённые и новые файлы, dirty-подмодули; что вошло в снимок и что исключено.
- Путь окончательной сборки, marketing/build version, SHA-256 главного файла,
  подпись; отдельно путь и версия установленного приложения. Установка не подразумевается.
- macOS, архитектура, размер экрана, масштаб и размеры текста, доступность UI,
  активные запись/обработка, доступные модели и тестовые данные.
- Фактические исполнители, модели, reasoning, замены и число агентов.
- Набор обязательных ID и причина добавления проверок по изменениям.

| ID | Обязателен | Статус | Что наблюдали | Доказательство | Ограничение/следующий шаг |
| --- | --- | --- | --- | --- | --- |
| UI-… | Да/нет, причина | PASS/FAIL/BLOCKED/NOT RUN | Конкретный результат | Лог/снимок/ответ пользователя | … |

У каждого ID матрицы должна быть строка. Для `NOT RUN` укажи причину: вне режима,
не затронуто, не выполнено. Пропуск обязательного ID препятствует положительному
вердикту. Неприменимую возможность обозначай `NOT RUN` и объясни применимость;
потерянную при сборке существующую функцию не объявляй неприменимой.
PKG-03 не входит в обязательный охват audit-only: он обязателен лишь при
отдельном поручении установить приложение. Отсутствие согласованного сеанса
для других уже обязательных аппаратных/ASR сценариев означает BLOCKED.

## Значение статусов

- **PASS** — ожидаемое поведение наблюдалось на указанном снимке; приложено
  соответствующее доказательство. Старый отчёт отдельно помечается историческим.
- **FAIL** — воспроизведено нарушение ожидания. Укажи шаги, ожидаемое и фактическое,
  важность, область воздействия; неизвестное происхождение не отменяет ошибки.
- **BLOCKED** — проверку не удалось завершить из-за конкретной внешней причины:
  блокировка Mac, отсутствие разрешения/оборудования/корпуса, занятость ресурсов,
  неподтверждённая физическая клавиатура, отсутствие делегирования.
- **NOT RUN** — проверка не запускалась. План, чтение кода и успешный компилятор
  не дают `PASS` поведению UI или настоящей записи.

## Общий вердикт

1. Любой актуальный `FAIL` → **FAIL**, даже если не связан с новой задачей.
2. Нет FAIL, но обязательный ID заблокирован → **BLOCKED**.
3. Нет FAIL/BLOCKED, но обязательный ID не выполнен → **NOT RUN / неполный**.
4. Все обязательные ID прошли → **PASS в режиме …**, с явным списком исключённого.

Всегда покажи счётчики `PASS / FAIL / BLOCKED / NOT RUN`, обязательный охват
`прошло / требовалось`, оставшиеся исторические ограничения и риск для выпуска.
Ежедневный PASS не означает полный release PASS. Четыре статуса проверки
не заменяют жизненный цикл бага: «исторически не закрыт» ещё не доказывает
его наличие в сегодняшней сборке и не становится сегодняшним PASS без воспроизведения.

Короткий ответ пользователю: вердикт, версия/снимок, найденные ошибки,
существенно непроверенное и ссылка на отчёт. Не перечисляй все зелёные пункты.
