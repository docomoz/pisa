# Размещение на отдельном Ubuntu VPS

Комплект предназначен для нового выделенного сервера. Он не покупает сервер, не меняет DNS и не заменяет конфигурацию других сайтов. Нужны Node.js 22 или новее по пути `/usr/bin/node`, Caddy, systemd и доступ с правами sudo. На сервере должны быть открыты входящие TCP-порты 80 и 443; порт приложения 4173 слушает только `127.0.0.1` и наружу не открывается.

Сервер должен обращаться к GitHub по HTTPS: `/download` при каждом запросе получает appcast последнего релиза, проверяет адрес DMG и перенаправляет на него. При ошибке показывает страницу с ссылкой на релиз вместо устаревшего файла.

## Подготовка пакета

В проверенном исходном состоянии репозитория выполнить на машине с Node.js 22+, где доступен `tar`:

```sh
cd website
npm test
node scripts/package-vps.mjs /tmp/pisya-site.tar.gz
```

Пакет содержит собранную серверную часть вместе с ресурсами страницы, unit для systemd, конфигурацию Caddy и установщик. Учётные данные, сайт Sites и другие файлы из проекта в него не включаются. Служебный `.openai/hosting.json` для сборки пакета не нужен.

Публичный идентификатор веб-потока Google Analytics 4 хранится в `analytics.json` в поле `gaMeasurementId`: обычные сборки автоматически подхватывают его. Пустая строка отключает аналитику. Для разового переопределения задайте `PISYA_GA_MEASUREMENT_ID` в окружении сборки; переменная имеет приоритет, а пустое значение явно отключает счётчик. Сборка выводит используемый идентификатор или `disabled` — перед публикацией проверяйте это значение. События: `page_view`, `install_guide_click`, `download_click`, `github_click`, `copy_install_command`. В настройках потока GA4 отключите расширенную статистику по исходящим ссылкам и скачиванию файлов, чтобы не считать их дважды. Параметры URL и текст, введённый посетителем, в события явно не передаются.

## Установка

Проверить IP нового сервера, ключ SSH, что этот IP отличается от IP Mapfav, и что выбран нужный отдельный аккаунт. Установить Node.js и Caddy из их официальных источников. Скопировать пакет на сервер, указав его адрес и имя пользователя вместо примера:

```sh
scp /tmp/pisya-site.tar.gz USER@SERVER:/tmp/pisya-site.tar.gz
```

Подключиться к серверу и установить приложение:

```sh
mkdir -p /tmp/pisya-site-install
tar -xzf /tmp/pisya-site.tar.gz -C /tmp/pisya-site-install
sudo sh /tmp/pisya-site-install/deploy/install.sh
curl -i http://127.0.0.1:4173/
curl -I http://127.0.0.1:4173/download
```

Установщик сохраняет каждую версию отдельно в `/opt/pisya-site/releases/`, переключает ссылку `current` и перезапускает только `pisya-site.service`. Он не затрагивает Caddy и откажется перезаписывать не принадлежащий этому комплекту unit. Для обновления повторить сборку, копирование и установку нового пакета.

## Домен и HTTPS

В DNS задать для `pisya.app` и `www.pisya.app` A-записи на новый IP. Запись AAAA добавлять только при настроенном и проверенном IPv6 этого сервера. Не включать проксирование DNS-провайдером, если требуется, чтобы публичный IP домена был именно IP VPS. Дождаться, пока обе записи действительно укажут на сервер, прежде чем включать HTTPS.

Файл `deploy/Caddyfile` содержит конфигурацию двух имён: `pisya.app` проксирует запросы к приложению, `www.pisya.app` перенаправляет на основной домен. На выделенном сервере добавить содержимое файла в действующую конфигурацию Caddy либо подключить его через `import`; не затирать чужие настройки. Затем проверить и применить итоговую конфигурацию:

```sh
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

Caddy получает и обновляет TLS-сертификаты автоматически после того, как оба имени указывают на сервер и порты 80/443 доступны извне. Проверить с внешней сети `https://pisya.app/`, переход с `https://www.pisya.app/`, сертификат, внешний IP и `/download` (включая реальное начало скачивания DMG в браузере). Если GitHub с IP VPS недоступен, `/download` честно вернёт 503; это нужно проверить именно после переноса. Логи приложения: `journalctl -u pisya-site.service`.
