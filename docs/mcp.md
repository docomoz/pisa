# Доступ к библиотеке Pisya через MCP

Подключённый клиент может искать встречи, читать сохранённые расшифровки и ссылаться на конкретные реплики. Данные о встречах в корзине недоступны.

## Инструменты

| Инструмент | Что возвращает | `limit` по умолчанию и диапазон |
| --- | --- | --- |
| `list_meetings` | Встречи с датой, участниками, папкой и состоянием расшифровки, без текста реплик | 30, от 1 до 100 |
| `search_meetings` | Встречи, в которых подстрока `query` найдена в названии, источнике, заметках, именах участников или тексте реплик | 50, от 1 до 100 |
| `read_transcript` | Расшифровку встречи по обязательному `meeting_id` | 100, от 1 до 100 |
| `list_folders` | Идентификаторы и названия папок и число встреч вне корзины в каждой из них | Без параметров и страниц |
| `search_transcripts` | Реплики по обязательному `query`, соседние реплики и сведения о найденных встречах | 10, от 1 до 50 |

В обоих инструментах поиска `query` содержит от 1 до 500 символов. `search_meetings` ищет подстроку без учёта регистра. `search_transcripts` ищет слова в тексте одной реплики без учёта регистра и разницы между «ё» и «е». Пунктуация разделяет слова. Поиск учитывает именно сохранённую словоформу.

- `all_words` по умолчанию находит реплики со всеми словами запроса в любом порядке. Совпадения по фразе идут первыми.
- `exact_phrase` находит последовательность слов в порядке запроса без промежуточных слов.
- `context` задаёт число соседних реплик с каждой стороны, от 0 до 3, по умолчанию 1. Соседи могут принадлежать другим спикерам.

`list_meetings`, `search_meetings` и `search_transcripts` принимают фильтры `folder_id`, `meeting_id`, `speaker`, `date_from` и `date_to`. Для папки и встречи передайте UUID. Фильтр `speaker` сравнивает полное сохранённое имя длиной до 200 символов, без учёта регистра, разницы между «ё» и «е» и повторяющихся пробелов. В `search_transcripts` фильтр применяется к совпавшей реплике. В списке и поиске встреч достаточно одной реплики этого участника во встрече.

Даты фильтруют время начала встречи. `date_from` входит в диапазон, `date_to` задаёт исключённую верхнюю границу. Передавайте время в формате ISO 8601 с `Z` или смещением часового пояса, например `2026-11-05T09:00:00+03:00`. Можно указать до девяти знаков после точки в дробной части секунды.

## Страницы результатов

Начальный `offset` равен 0. Допустимый диапазон — от 0 до 1 000 000 000. Пока `has_more` равен `true`, передавайте `next_offset` в следующий запрос с теми же фильтрами. `complete: true` означает, что текущий ответ охватывает всю выдачу с нулевого смещения. На последней странице, запрошенной с ненулевым смещением, `has_more` и `complete` оба равны `false`.

Каждый запрос читает актуальную библиотеку. Запись, повторная расшифровка и редактирование могут изменить порядок и состав выдачи между страницами. Для сопоставления результатов используйте идентификаторы встреч и реплик.

## Реплики и ссылки

`read_transcript` и `search_transcripts` возвращают сохранённый текст реплики без перефразирования, её UUID, спикера, индекс и время начала и конца в секундах. В ответе `search_transcripts` совпадение находится в `segment`, соседи — в `context_before` и `context_after`.

Поле `source_url` содержит локальную ссылку `pisya://` с UUID встречи и реплики, а также отметкой времени. Pisya открывает встречу, выделяет реплику и запускает доступное аудио. Если после повторной расшифровки или редактирования UUID реплики исчез, приложение выделяет ближайший фрагмент по времени и предупреждает о приблизительном совпадении. В этом случае аудио автоматически не запускается. Если аудио недоступно, сохранённый текст можно прочитать.

## Качество и полнота расшифровки

Объект `quality` есть у встреч и реплик. `transcript_state` описывает состояние сохранённой расшифровки.

| Состояние | Значение |
| --- | --- |
| `pending` | Обработка ещё не началась |
| `processing` | Обработка идёт, граница черновика не сохранена |
| `draft` | Есть отметка о черновике, текст может измениться |
| `partial` | Обработка завершилась ошибкой после сохранения части черновика |
| `failed` | Обработка завершилась ошибкой, сохранённая граница черновика не подтверждает обработанный отрезок |
| `final` | Обработка завершена, включая случай, когда распознанного текста нет |

`processing_status` передаёт сохранённое состояние обработки. `live_committed_until_seconds` указывает сохранённую границу черновика, когда она известна. `warnings` содержит коды конкретных ограничений, например `no_transcript_text` при отсутствии текста.

`transcript_complete: true` означает завершение обработки. Флаг `complete` на верхнем уровне относится к странице результатов. Охват записи (`recording_coverage`) и ручная проверка (`human_verification`) имеют значение `unknown`. Уверенность распознавания (`recognition_confidence`) имеет значение `not_measured`. Отсутствие совпадений показывает только результат поиска по сохранённому тексту.

`speaker_identification` различает неизвестного спикера (`unidentified`), метку микрофона «Я» (`self`) и сохранённое имя (`named`). Сохранённое имя само по себе не подтверждает личность. Сводка встречи содержит число реплик без идентифицированного спикера в `unidentified_speaker_segment_count`.

`audio_availability` описывает наличие файлов в списке аудио встречи. `available` означает, что нужные файлы найдены, `partial` — найдена часть файлов встречи, `missing` — нужных файлов нет или они недоступны, `none` — список аудио встречи пуст. `audio_playability: not_checked` означает, что MCP не проверяет воспроизведение файла и наличие звука в интервале конкретной реплики.

## Доступ и конфиденциальность

Для Codex добавьте установленный сервер командой `codex mcp add pisya -- /Applications/Pisya.app/Contents/Helpers/pisya-mcp`, затем обновите подключение в настройках MCP-клиента.

Если macOS запрещает чтение библиотеки, откройте **Конфиденциальность и безопасность → Файлы и папки**, раскройте строку MCP-клиента и включите доступ к **Pisya**. Достаточно разрешения для этого приложения. При таком отказе сервер возвращает пояснение о доступе; ошибка запроса списка инструментов имеет формат JSON-RPC, а ошибка вызова инструмента — `isError: true`.

Сервер работает локально без сетевого порта и предоставляет только чтение. В ответах нет аудиоданных, локальных путей к файлам и голосовых эмбеддингов. Подключённый клиент может передавать полученный текст своему провайдеру.

Чтобы отозвать доступ, откройте раздел **MCP** в настройках Pisya и выключите **Разрешить MCP читать библиотеку**. Это блокирует следующие запросы инструментов, в том числе от уже подключённого клиента. Клиент может хранить ранее полученный текст.

## Пример запроса

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "search_transcripts",
    "arguments": { "query": "срок релиза", "mode": "exact_phrase", "context": 1, "limit": 5 }
  }
}
```
