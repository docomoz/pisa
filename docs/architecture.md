# Pisa

Нативное приложение для macOS 15 и новее, Apple Silicon. Основной сценарий — запись онлайн-встреч в Контур Толке. Библиотека, аудио и обработка находятся на компьютере пользователя.

## Границы доступа

Приложение работает в App Sandbox с разрешением network.client для загрузки моделей. Разрешение network.server отсутствует. При первой настройке нативный URLSession загружает файлы с Hugging Face; распознавание выполняется локально. Аудио и расшифровки для распознавания не отправляются.

Комплект моделей задаётся встроенным manifest с размерами и SHA-256. Каждый файл загружается во временный файл, проверяется потоком вне главного потока и атомарно заменяет целевой файл. Отмена прерывает загрузку и проверку, удаляя незавершённый файл; готовые файлы используются повторно. Перед загрузкой проверяется свободное место. При запуске проверяется полный комплект, включая модели участников. Пользовательская папка MLX поддерживается через security-scoped bookmark; для неё проверяется структура, без привязки весов к хешам стандартной модели.

Пока окно первой настройки открыто или идёт загрузка, ручная и автоматическая запись не начинаются. «Позже» разрешает сохранять аудио без расшифровки. Разрешения микрофона и системного звука запрашиваются существующим сценарием при первой записи.

Экспорт в выбранную папку разрешается пользователем. Если папка обслуживается Dropbox, iCloud или другим сервисом синхронизации, этот сервис получает текст. Аудио автоматически не экспортируется.

MCP работает как отдельный процесс через stdio, без сетевого порта. По умолчанию доступ включён; ранее сохранённое отключение остаётся в силе. Каждый запрос перепроверяет переключатель. Доступны списки встреч и папок, поиск встреч и реплик, чтение исходного текста с метаданными качества. Ссылки `pisa://meeting/…` открывают приложение на нужной реплике; аудиофайлы, пути хранения, голосовые векторы и изменение данных через протокол недоступны. Подключённый клиент может отправить прочитанный текст своему провайдеру. MCP не защищает данные от других программ, уже имеющих прямой доступ к пользовательским файлам. Контракт поиска, страниц и метаданных описан в [документации MCP](mcp.md).

## Запись

Core Audio Tap получает системный звук без аудио самого приложения. Отдельная AVCaptureSession записывает микрофон. CAF-дорожки синхронизируются по временным меткам macOS. Видео не сохраняется. Захват не зависит от запуска Толка, браузера или другого клиента звонков; запись можно начать заранее.

Перед распознаванием микрофона WebRTC AEC3 использует системную дорожку как опорный сигнал. Выравнивание учитывает изменения задержки. Исходники не переписываются; обработка создаёт отдельный производный файл. Эффективность зависит от акустики и устройств.

Для коротких фрагментов словарь встречи не передаётся в модель. На микрофонной дорожке для фрагментов до полутора секунд язык берётся из явного ответа модели. Если модель вернула поддерживаемый язык помимо русского и английского, фрагмент повторно распознаётся на русском.

При отмене короткого распознавания его производитель сначала завершается, затем освобождается модель. Новый проход не начинается одновременно с предыдущим отменённым проходом.

Автодетект опрашивает аудиопроцессы Core Audio раз в две секунды. Использование микрофона другим приложением запускает трёхсекундное ожидание, неактивность — 45-секундное ожидание завершения. Только воспроизведение звука не является триггером. Для заранее начатой ручной записи автостоп включается после обнаружения активности. Ручная остановка подавляет новый старт до окончания активности. Использование микрофона не гарантирует звонок: диктовка и тест устройства могут давать ложные сигналы; отключение микрофона при mute может вызвать автостоп. Режим выключен по умолчанию и требует проверки на реальных звонках.

## Данные

Каждая встреча хранится отдельным JSON-файлом, запись атомарная. Аудио хранится отдельно. Имена файлов создаются из UUID; экспорт использует стабильное имя по UUID и обновляет его после правок. Исходные пользовательские аудиофайлы при импорте копируются, а не перемещаются.

Обработка сериализована: одна модель и одна встреча одновременно. Во время записи обрабатываются подтверждённые участки, модель используется повторно. Черновик и граница обработанного аудио сохраняются атомарно. После остановки обрабатывается оставшийся хвост и уточняется разметка участников, затем модель освобождается. Обработку можно приостановить отдельно от записи. При сильном нагреве она откладывается. При отсутствии подтверждённого системного аудио или безопасной границы длинной реплики черновик может ждать завершения записи.

Silero определяет речь на микрофонной дорожке. Pyannote выделяет речевые области собеседников, TitaNet вычисляет голосовые признаки. Имена сохраняются в профили только отдельным действием пользователя; неоднозначные совпадения не присваиваются автоматически. После перезапуска незавершённый хвост остаётся доступен для продолжения, исходное аудио сохраняется.

Русские фразы длительностью от двух секунд дополнительно распознаёт GigaAM-v3 e2e RNNT на CPU. Если варианты различаются словами, Qwen3-ASR повторно декодирует то же аудио с акустическим вариантом GigaAM и пользовательским словарём в контексте. Текст не исправляется заменами по списку ошибок. Пустые, иноязычные и сильно укороченные результаты отклоняются; уже распознанные фразы из словаря должны сохраниться. Развёрнутые английские реплики остаются на первом проходе. Оба распознавателя переиспользуются между окнами живой записи и освобождаются при её завершении. При недоступности дополнительной модели сохраняется первый результат.

После первого прохода `RecognitionContext` сопоставляет реплики обеих дорожек в хронологическом порядке. Снимок этого прохода остаётся неизменным: принятое исправление не подтверждает следующие исправления того же прохода. При живой обработке и возобновлении дополнительно используются уже сохранённые реплики за последние 300 секунд. Для подсказки берутся ближайшие реплики и до четырёх подходящих словарных терминов; цитаты и служебные токены исключаются. Словарь и соседний текст помогают повторно распознать аудио, но не считаются произнесёнными словами. Копирование подсказки запускает повтор без неё.

Если полная реплика остаётся неоднозначной, временные метки GigaAM позволяют найти короткий фрагмент по уникальным окружающим словам. Повтор выполняется на той же очищенной от эха дорожке. Правка ограничена одним согласованным участком текста; время, голос и ссылка на аудио сохраняются. Для смешанного написания аббревиатуры с русским окончанием дополнительно нужны установленный в соседней речи термин и совпадение букв в двух различных окнах без подсказки. Это контекстный выбор написания акустически неоднозначного окончания, а не независимое доказательство падежа. Явное конкурирующее название, цитата, код или диктовка символов запрещают такую правку.

Короткая латинская реплика до трёх секунд перепроверяется Qwen3-ASR с русским языком. Для неоднозначного междометия вроде `Uh huh` допускается только русское междометие из этого аудио: сначала результат Qwen3-ASR, а если он не подходит — GigaAM. Для обычных слов дополнительно нужно совпадение с независимым акустическим результатом GigaAM: принудительный язык сам по себе может переводить настоящую английскую речь. В обоих случаях ближайшая содержательная реплика должна подтверждать русский язык, а явно распознанное написание из словаря сохраняется. Предпочтение отдаётся той же дорожке; контекст ограничен 60 секундами и сбрасывается вместе с сессией.

В настройках сохраняются базовые термины. `SpokenVocabulary` готовит их произношения из встроенного CMUdict, названий английских букв и цифр, транслитерации и русских окончаний; результат переиспользуется до изменения словаря. Например, запись `PNL` позволяет оформить услышанное окончание как `PNL'ку`, не добавляя форму в настройки. Произношения применяются к результатам обоих распознавателей до повторного декодирования. Близкие, но не совпавшие варианты длинных названий используются только как подсказка для нового распознавания аудио; короткие сокращения этим способом не заменяются. Неоднозначные совпадения отклоняются, отдельные предлоги и местоимения сохраняются. Числовые сокращения дополнительно нормализуются по произнесённому числу и падежу. Все операции выполняются локально; пользовательский словарь не передаётся источнику CMUdict.

Пять файлов GigaAM (около 232 МБ) загружаются из закреплённой ревизии с проверкой SHA-256; лицензия MIT сохраняется вместе с ними. Модель применяется одинаково при живой и полной расшифровке.

После полной расшифровки Qwen3-1.7B-4bit формулирует короткое название по содержанию беседы. Длинный текст последовательно сворачивается в промежуточные выжимки; обрабатываются все части, включая завершение встречи. Модель названий загружается однократно по отдельному manifest с проверкой размера и SHA-256, затем работает локально. Текст встречи не передаётся серверу загрузки моделей.

Источник названия сохраняется в JSON. Название, заданное человеком, не заменяется при повторной обработке; смысловое название не сбрасывается в дату при запуске приложения. Расшифровка сохраняется до генерации названия: ошибка этой дополнительной операции оставляет готовый текст и прежнее название.

## Поставка

`scripts/build.sh` создаёт приложение и DMG с Applications, фоновым изображением и стрелкой переноса. В приложение включены нативные динамические библиотеки, Metal-ресурсы, помощник MCP и лицензии. Python, Homebrew и Xcode на Mac пользователя не требуются.


Исходники доступны в публичном репозитории `docomoz/pisa`. MLX Audio подключён как открытый подмодуль на фиксированном коммите. Патч MLXFFT применяется скриптом сборки. Скрипт упаковки использует идентичность из локального файла `.signing.env`, если она настроена; иначе применяется ad-hoc подпись. Ключи и параметры личного сертификата не включаются в репозиторий. Проверка целостности подписи выполняется после добавления библиотек, помощника MCP и лицензий. Подпись Developer ID и нотариальное заверение Apple нужны для обычного распространения на другие Mac; текущая локальная сборка не объявляется нотариально заверенной.
