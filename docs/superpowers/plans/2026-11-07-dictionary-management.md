# План управления словарём

**Цель:** отдельный экран для поиска, добавления, изменения и удаления терминов без переписывания существующего словаря.

**Основа:** SwiftUI, AppKit, текущий `Preferences.vocabulary: String`; новых зависимостей нет.

**Спецификация:** `docs/superpowers/specs/2026-11-07-dictionary-management-design.md`, согласована пользователем 7 ноября.

## Ограничения

- Изолированная рабочая копия `/private/tmp/pisya-dictionary-screen`; чужие изменения основного проекта не переносить в коммиты.
- Существующие написания, порядок и повторы сохраняются. Открытие и поиск ничего не сохраняют.
- Операции применяются к актуальному словарю. Сохранение на диск предшествует обновлению состояния.
- Поиск, длинные строки, пустые состояния, увеличенный текст и клавиатура проверяются в работающей сборке.
- Интервалы — `PisyaDesign.Spacing`, заголовки — `SectionHeading`, кнопки без внешней обводки, доступные с клавиатуры.
- Один агент реализации за раз; короткий отчёт. Проверки — отдельному более экономному агенту. Коммиты и интеграцию выполняет координатор.

## Риски проверки

- Смешанные разделители и старые повторы: удаление одного вхождения не трогает соседние записи.
- Словарь обновился при открытой форме: добавленный из разметки термин не теряется.
- Отмена удаления после нового добавления сохраняет и восстановленный, и новый термин.
- Вставка повторов аббревиатур: предварительный просмотр совпадает с общим механизмом добавления.
- Ошибка записи не показывает ложный успех и не очищает ввод.

### Task 1: операции со строковым словарём

Файлы: новый `Sources/PisyaCore/VocabularyDictionary.swift`, новый `Tests/PisyaCoreTests/VocabularyDictionaryTests.swift`.

Интерфейс (публичный, доступный также в приложении):

- `VocabularyDictionary.entries(in: String) -> [VocabularyDictionary.Entry]`, Entry: Identifiable, Equatable, `text: String`; хранит исходную строку и диапазон для проверки актуальности.
- `VocabularyDictionary.replacing(_ entry: Entry, with: String, in: String) throws -> String` — явное новое написание, проверка пустоты, разделителей, повторов, актуальности; не выводить основу вместо введённой формы при редактировании.
- `VocabularyDictionary.removing(_ entry: Entry, from: String) throws -> VocabularyDictionary.Removal`; Removal: `vocabulary: String`, `restoring(in: String) throws -> String`.
- `VocabularyDictionary.preview(_ input: String, vocabulary: String) -> VocabularyDictionary.Batch`; Batch: `additions: [String]`, `duplicates: [String]`, `invalid: [String]`, `emptyCount: Int`, `vocabulary: String`.

Диапазоны изменяют только выбранное вхождение, прочие данные не пересобираются. Консервативно отклонять устаревшую операцию с понятной ошибкой; последующее дописывание терминов в конец должно допускаться. Отмена не заменяет всю актуальную строку старой копией. Предварительный просмотр добавления использует `TranscriptTerms.adding` последовательно для всех элементов. Каноническое добавленное написание берётся из результата добавления, без отдельного разбора аббревиатур: это работает и с текущей, и с будущей версией правил. Разделители: запятая, точка с запятой, CR/LF. Сохранённые пустые элементы не становятся записями.
